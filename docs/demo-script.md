# Demo Script

This is a 2 to 3 minute founder-facing walkthrough for ThoroughLoop.

## Opening Pain Statement

Early-stage founders rarely have one clean source of truth.

Sales notes live in one place. Customer feedback is in calls and support messages. Hiring feedback is scattered. Investor update notes are half-written. The problem is not that the founder needs another system. The problem is that messy context does not become a clear decision.

## What ThoroughLoop Does

ThoroughLoop turns messy founder context into one operating loop:

```text
Diagnosis -> memo -> action -> decision -> review
```

The goal is to help a founder move from scattered notes to one clear next step and one decision to revisit later.

## Messy Input Example

Here is a realistic sales example:

```text
FinCore Labs liked the demo but the pricing call went sideways. BrightLayer AI has not replied since the proposal. Northstar Ops asked for a security review but no one owns the next step. I keep adding leads, but the late-stage deals feel stuck.
```

## Diagnosis

After the context is pasted, ThoroughLoop identifies the operating pattern.

In this example, the issue is not just needing more leads. The bottleneck is late-stage follow-up clarity.

## Founder Memo

The product turns the messy input into a short founder memo.

The memo explains the problem, the evidence, what is missing, and why this should get founder attention now.

## One Action

Instead of creating a long task list, the loop gives one founder-level action.

For this example, the action is to pick the highest-risk late-stage account and send one founder-led follow-up asking for the next decision step.

## One Decision

The loop also saves one decision to review.

For this example, the decision is whether founder attention this week should go to late-stage recovery before adding more top-of-funnel work.

## Review Loop

The important part is not only generating a memo. It is coming back later to review the decision.

Next week, the founder can ask: did the follow-up create a clear next step, or should the account be parked?

## Closing Ask For Feedback

The feedback I want is not whether this looks polished.

I want to know whether this maps to a real workflow:

- Where does your founder context usually get scattered?
- Does this diagnosis, action, decision, and review loop feel useful?
- Which use case would you test first: sales, customer feedback, hiring, or investor updates?
- What would make this more useful or more trustworthy?
